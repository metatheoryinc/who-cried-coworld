# Scoring Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement `2026-09-24-scoring-design.md`: headline `0.75 × win + 0.25 × bonus` with Town `read` and Wolf `hidden` bonuses from private suspicion reports, plus metric columns, in `wcw.results/2`.

**Architecture:** A pure module `src/game/domain/scoring.ts` computes scores and metrics from plain inputs. `Session.finish` builds those inputs from the journal (suspicion events, ballots, eliminations, failures) and request counters, then publishes the augmented result in the `finished` event. The rules still decide the outcome. Suspicion arrives as an optional field on Town votes, is sanitized (invalid → missing), and is journaled as a server-only `suspicion` event with a new `beliefs` reveal.

**Tech Stack:** TypeScript, Zod 4, Vitest.

---

### Task 1: Scoring module

**Files:** create `src/game/domain/scoring.ts`, `tests/domain/scoring.test.ts`.

Inputs: `seats` (faction per slot), `winners` (slot set, empty on draw), `votes` (`{day,slot,target|null,living[],livingWolves}` per ballot), `reports` (`{day,slot,probs:Map<slot,number>}` per accepted suspicion), `townVoters` per day (living Town slots asked), `deathDay` per slot, `daysCompleted`, `requests`/`fallbacks` per slot.

Tests first: perfect report → read 1; baseline report or missing → 0; worse than baseline → 0; wolf never suspected → hidden 1, suspected at chance → 0, day with no reports → 0; draw → win 0 with bonus kept; headline formula; `vote_hit` chance-normalized and omitted with no non-skip votes; `read`/`vote_hit` omitted for Wolves, `hidden` omitted for Town; `survived`; `valid_actions`.

### Task 2: Results v2 and replay compatibility

**Files:** `src/shared/results.ts`, `src/shared/replay.ts`, `src/game/domain/rules.ts`, tests.

`ResultsV1` (existing, readable) and `ResultsV2` (`schema:'wcw.results/2'`, `scores: number[9]` in [0,1], `metrics: 9 objects with optional win/read/hidden/vote_hit/survived/valid_actions`); `Results` = union for parsing, v2 produced. Rules produce v2 with win-only scores and `{win}` metrics; draws no longer force all-zero scores but do force `win = 0`.

### Task 3: Suspicion protocol and journal

**Files:** `src/shared/player.ts` (vote request `suspicion?: true`), `src/shared/actions.ts` (vote body `suspicion?: Record<string, number>` bounded), `src/shared/events.ts` (payload `suspicion {slot, probs:[{slot,p}]}`, reveal `beliefs`, server-only), `src/game/runtime/session.ts` + `human-session.ts` (request flag for Town; on vote close, sanitize and emit), tests (`tests/runtime/suspicion.test.ts`).

Sanitize: keys must be exactly the other living slots, values finite in [0,1]; otherwise dropped. Never affects legality. Not present in observations or snapshots.

### Task 4: Score at game end

**Files:** `src/game/runtime/session.ts` (`finish`), tests. Build scoring inputs from the journal and counters; replace result scores/metrics before emitting `finished`. Scripted episode test: results parse as v2, metrics present per applicable seat.

### Task 5: LLM policy and scripted baseline

### Task 6: Replay viewer
